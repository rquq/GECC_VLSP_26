# Kaggle filename-loaded launcher import fix — 2026-10-15

Fixed and locally verified; source41c6435. The provided Kaggle run passed dependency imports with Torch2.11.0+cu128/CUDA12.8, then failed in notebook In[4], before the experiment started: tools/notebook.py tried importing model.reproducibility from the notebook kernel. The notebook loads that file as gecc_notebook with importlib; kernel cwd/sys.path do not include the cloned project. Setting cwd on a future child process does not fix imports in the parent kernel. The relative .process_groups cleanup import would independently fail because gecc_notebook has no parent package.

This supports the existing notebook's filename loader, so no notebook toggle/cell or dataset reupload is required.
